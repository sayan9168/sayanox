## Local increment: validated nested value replacement

`jd_set_raw` replaces an existing dotted-path value after validating both JSON
inputs, preserving the surrounding bytes and exact numeric text. Missing paths
and malformed inputs return an empty string. `jd_delete_raw` removes an
existing non-root value; `jd_object_put_raw` inserts or replaces a member of
an existing object using a JSON-encoded key. `jd_array_insert_raw` inserts at
a validated index in an existing array or appends at its length. Creation of
missing intermediate objects is supported by `jd_object_ensure_raw`; creating
missing arrays or inferring container types remains open. The expanded
hand-written boundary oracle passed
`./sx target test-stdlib-next` locally on seed-min, gen2 and native. This is
not fresh guarded complete CI or closure of R07.

## Local increment: bounded exact decimal arithmetic

`stdlib/decimal.sa` provides a separate string representation with exact
comparison, addition, subtraction, multiplication, rounded division and
half-away rounding for up to 256 digits. Invalid inputs, division by zero and
oversized results are refused. Hand-calculated boundaries and independent Python-decimal vectors
pass
`test-stdlib-next` on seed-min, gen2 and native. This increment is not complete
guarded CI or closure of R07.

## Local increment: exact decimal JSON updates

`stdlib/json_decimal.sa` reads and updates existing JSON numbers using the
bounded exact-decimal representation, preserving other source bytes and
rejecting malformed input, absent/nonnumeric paths and exponent notation.
Its independent boundary oracle runs on seed-min, gen2 and native through
`test-stdlib-next`. This does not close R07 or replace complete guarded CI.

## Local increment: CSV document tables

`stdlib/csv_table.sa` parses and writes multi-row CSV, validates packed frames,
updates cells, filters and projects rows with explicit byte/row/field caps.
The independent boundary and round-trip oracle passes `test-stdlib-next` on
seed-min, gen2 and native. This does not close stdlib depth or replace complete
guarded CI.

## Local increment: bounded CSV queries

`stdlib/csv_query.sa` provides stable joins, distinct, bytewise sorting and
exact decimal sums, means and grouping over CSV tables. Boundary, invalid-input
and cross-backend output oracles run through `test-stdlib-next`. This does not
close stdlib depth or replace complete guarded CI.

### Increment log - 2026-11-17 (bounded byte regular expressions)

* **R07 - patterns without a host engine:** `stdlib/regex.sa` is a backtracking
  VM over a flat code list, not a recursive matcher, so matching depth is the
  pattern's nesting and never the subject's length. Code is emitted with
  relative jumps computed from each fragment's own size, which avoids
  backpatching in a language whose lists cannot be assigned element by element
  on every backend. Captures live in an append-only arena of fixed-width
  vectors: a save appends a copy with one slot changed and the alternative
  stack stores only the arena offset, so backtracking restores captures without
  mutating anything.
* **Python's preference order, not POSIX's:** alternatives are tried left to
  right, `a*` is greedy, `a*?` is lazy, and `rx_full` compiles an end-of-subject
  test *inside* the program so the VM backtracks out of a shorter alternative
  (`a|ab` fullmatches `"ab"`). `rx_find_all` implements Python's post-3.7
  empty-match rule: after an empty match the search resumes at the same offset
  with an empty match refused, which the first implementation got wrong and the
  fuzz corpus caught on `.*?`.
* **Refusals are the feature.** Backreferences, lookaround, inline flags, named
  groups, possessive quantifiers, POSIX classes, unknown letter escapes,
  inverted ranges and unterminated constructs are refused instead of
  reinterpreted; `[[:alpha:]]` silently becoming a class of `[`, `:`, `a`, `l`,
  `p`, `h` was a real defect in the first draft. An unbounded repetition whose
  body can match the empty string is refused too, because that is the shape
  that loops forever in a backtracking engine.
* **Limits, stated:** 200-byte pattern, 1024-byte subject, 16 groups, 256
  matches per find-all/replace, 250,000 steps per anchored attempt. Budget
  exhaustion answers -1, apart from "no match" (0), and a whole search costs up
  to `len(subject)+1` attempts, which the documentation says rather than hides.
* **Oracle:** 288 frozen expectations; 256 computed outside Sayanox with Python
  3.11 `re` in `re.ASCII` mode and 32 hand-written contract rows for the
  refusals and limits. Fuzzing beyond the fixture (3,520 pattern/subject rows
  and 720 replacement rows, not tracked) found four defects: a class after a
  group reset the group count, unset groups started at 0 instead of -1, an
  invalid `{m,n}` fell back to literal text, and fullmatch could not backtrack
  into a longer alternative.
* **Portability:** the fixture is plain portable Sayanox - no list element
  assignment, no parenthesised string index in a condition, no `%` inside a
  list literal - so seed-min, gen2 and `native_aot` produce identical bytes.
  Three seed-min restrictions were hit while writing the module and are recorded
  by the code itself: an index by a call result inside a condition, a
  parenthesised expression whose first token is a string or list, and a
  parenthesised index inside a numeric expression.
