# Gate log — 2026-11-02 — R14 and R15 fixed

Two defects from the work register, fixed with gates that fail on the previous
code.

## R14 — a `concat` program's data image is now cross-ISA identical

### What was wrong

While laying the image out, the emitter wrote two arch-specific values into the
**data** segment:

1. every `concat` literal argument's `(pointer, length)` pair —
   `literal_base + offset`, where `literal_base` is `134520832` on i386 and
   `4202496` on AArch64/RV64IM;
2. the `concat` bump pointer's initial value —
   `patch32(data, heap_cursor_slot, dva + 65536)`.

Each image was correct for its own target, but the same program's data image
differed between targets, so the project's "three-way data-segment agreement"
assertion had to exclude `concat` programs. `chr_nested` (the first accepted
`concat` program) could only be checked by pinning the data-segment *size*.

Measured before the fix, `chr_nested` i386 vs AArch64 data segments differed in
18 bytes; after the fix, in 0.

### The fix

Both values are now written by the program, not baked into the image:

- a literal argument's pair is stored at the call site:
  `emit_push_imm2(base + offset)`, `emit_pop_acc`, then a fixup-addressed 4-byte
  store into the pair slot, and the same for the length. The slot stays
  zero-filled in the image;
- the bump pointer lives in a 4-byte slot at data offset `32` (`0..31` is the
  decimal print buffer) that the entry code initialises once with the target's
  own base — `134586368` on i386, `4268032` on AArch64/RV64IM. The layout-time
  `patch32` is gone, and the lazy "allocate the cursor slot at the first
  `concat`" branch is replaced by that fixed slot.

Programs without `concat` pay 4 zero bytes of data and one dead word of code.

The `xc_data_layout` helper introduced for the narrowed assertion is deleted;
`chr_nested` is compared byte-for-byte by the ordinary `xc_data` path.

## R15 — `sxbuild inventory` no longer counts gitignored C outputs

### What was wrong

`is_generated_c_artifact` knew the checked-in generator names plus a "has a
`.sa` peer" rule, but not the compiler's default output paths that `.gitignore`
already lists. Reproduced live by creating the six files:

```
$ for f in mini_out _smoke _out hello_out boot boot2; do echo 'int main(void){return 0;}' > selfhost/$f.c; done
$ ./tools/sxbuild inventory | grep non-anchor
  non-anchor .c/.h files:  6        <-- before the fix
  non-anchor .c/.h files:  0        <-- after the fix
```

A genuine untracked file is still counted, so this is not a blanket ignore:

```
$ echo 'int x;' > selfhost/stray.c
$ ./tools/sxbuild inventory | grep non-anchor
  non-anchor .c/.h files:  1
```

### The fix and its gate

`is_known_selfhost_c` names all six (`selfhost/boot.c`, `boot2.c`, `_smoke.c`,
`_out.c`, `mini_out.c`, `hello_out.c`) next to a comment that ties the list to
the `selfhost/*.c` entries in `.gitignore`.

`test-sxbuild` used to assert `non-anchor .c/.h files: 0` on a clean tree, which
is a tautology. It now:

1. creates all six gitignored defaults, runs `sxbuild inventory`, asserts `0`;
2. creates `selfhost/stray_untracked.c`, runs it again, asserts `1`;
3. removes all seven.

Negative control (fix disabled, `is_known_selfhost_c` never matching):

```
[FAIL] selfhost/seed_tests/sxbuild_gate/inv.out: pattern assertion: non-anchor .c/.h files: *0
```
