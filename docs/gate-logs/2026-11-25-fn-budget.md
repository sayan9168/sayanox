# 2026-11-25 — checked resource-budget contract (`@budget`)

Scope: one bounded increment adding a declared compile-time resource budget to
`make` declarations, with the checker in `tools/native32.sa`, an independent
model in `selfhost/budget_model.sa`, and erasure on every lane. Spec:
[`docs/BUDGET.md`](../BUDGET.md).

This is **not** memory safety, not termination, not WCET, and not a heap/RSS
bound. See "Honest limits" at the end.

## What went wrong, and what it changed

1. **The spec was wrong, not the compiler.** The first draft of `BUDGET.md` and
   the model both said an empty-origin list costs 16 *locals*. The compiler
   charges 17 (16 words of capacity plus the list's name slot) and refused its own
   spec. The spec and the model were corrected; the model then agreed with the
   compiler on every fixture. This is recorded rather than smoothed over because
   it is the failure mode the model exists to catch.
2. **The first §6 implementation was unreachable.** Charging the callee's whole
   requirement to the caller double-counted the caller's own frame, so §5's
   aggregate rule always fired first and control (c) could not fail. §6 was
   narrowed to a *diagnostic* choice — blame the single worst non-cyclic call —
   which is what BUDGET.md §6 actually asks for.
3. **Refusal counts alone are not coverage.** Controls (a) and (f) initially
   passed because `xc_refusals` only checks that compilation failed. Both were
   caught only after `bg_diagnostic()` pinned the message text of each rule. That
   is why 22 named diagnostic rows exist alongside the count.
4. **Erasure had to reach the runtime.** Stripping the annotation from the parse
   text was not enough: `sxadvance_lower` pushed its "advanced constructs used"
   marker unconditionally, which pulled `_sx_adv_fail` into the generated C and
   made `plain` and `plain_twin` differ. The strip now returns early when nothing
   advanced remains.
5. **`native_aot` and `sxc_native` were left out at first.** Parity failed on two
   lanes until `tools/sxinfer_lib.sa` stripped the line as well; deleting the line
   outright then broke their parsers on an empty statement, which is why the strip
   substitutes a comment and preserves line numbering.

## Honest limits

- A **declared static upper bound** over the constructs the current subset can
  cost. It is not a whole-program memory guarantee.
- **Not** a termination proof, **not** WCET, **not** heap/RSS for the
  conservative collector. Live allocation beyond the fixed caps (8 declarations,
  6 parameters, 60 local words, 64 frames, 32 struct types, 32 fields, 16-element
  empty-origin growth) and C-lane allocator overhead stay outside the contract.
- **Recursion cycles are refused** below the 64-frame cap, not analysed. A
  recursive function therefore cannot declare a tighter frames budget at all.
- `@budget` is **checked only by `native32`**. On `seed-min`, `gen2`,
  `native_aot`, `sxc_native` and the IR VM it is erased and an unsatisfied
  annotation is not reported. The gate proves erasure, not cross-lane checking.
- List `locals` cost for a growing list is 17 by measurement (16 + name slot); a
  literal list costs one word per element. Numbers written in `BUDGET.md` are
  pinned to this emitter, not to an abstract model, so a future emitter change
  must update both.
- **R04 (precise GC) and R02 (full native parity) stay open.**

## CI/CD repair (follow-up)

Two real defects were found after the first push, both by looking at GitHub Actions
rather than at a local gate.

### 1. The new gate was not wired into CI at all

`./sx target test-fn-budget` passed locally but ran **nowhere** in CI: it was absent
from `.github/workflows/ci.yml`, from the `native-test` aggregate, and from the
migration registry. A gate nobody runs is not coverage.

Fixed in three places:
- `.github/workflows/ci.yml` — its own step, `run: ./sx target test-fn-budget`,
  because it is the only place the annotation is actually *checked*; every other
  lane erases it, so nothing else in CI would notice a broken checker.
- `tools/sxaggregate_targets_lib.sa` — added to the `native-test` aggregate.
- `tools/sxmigration_lib.sa` — registered, so `./sx migration` covers it.
  Coverage is now **242 / 242** (was 241 / 241).

### 2. `Complete original acceptance` failed at exactly 1h30m

Run [45574765377](https://github.com/sayan9168/sayanox/actions/runs/45574765377),
job 139069841849: `The job has exceeded the maximum execution time of 1h30m0s`.
**No assertion failed** — the step was still running when it was killed.

Measured locally with a timed `./sx ci` on the final tree:

| | value |
|---|---|
| `./sx ci` | exit **0**, **4,155 s** (69.2 min) |
| previous CI job cap | 5,400 s (90 min) |
| headroom | 20.8 min (~30%) |
| `d8f0062` job on GitHub | 51.4 min (passed) |
| `be1e1ed` job on GitHub | 90.0 min (**timeout**) |

The chain was also A/B measured to rule out my own changes as the cause:
`native_c_emitter` on `compiler_min.sa` was **22,238 ms** at `d8f0062` vs **22,392 ms**
with the change (+0.7%), and `sxc_native` was 26,309 ms vs 25,267 ms (the new tree is
*faster*). So the budget work did not add the time; the job's margin was already thin
and a contended runner pushed it over.

Fix: both jobs of `ci.yml` raised from 90 to **180** minutes.

### 3. The gate that guards the timeout could not fail

`tools/sxstdlib_remaining_gates_lib.sa` pinned the *literal* string
`"    timeout-minutes: 90"` and required the count to equal the job count. That
punished *raising* the ceiling while happily accepting a drop to 30.

Replaced with a total rule: count declared budgets, count the two accepted forms
(exactly `90$`, or three digits `$`), and require `jobs - three - exactly == 0`.

Negative control on the rule itself (`.github/workflows/ci.yml` timeout varied,
gate re-run each time, file restored):

| declared timeout | verdict |
|---|---|
| 30 | REFUSE |
| 60 | REFUSE |
| 89 | REFUSE |
| 90 | ACCEPT |
| 120 | ACCEPT |
| 180 | ACCEPT |
| 360 | ACCEPT |

Two intermediate attempts were **wrong and were caught by this control**, not
shipped: `[1-9][0-9][0-9]*` accepted 30, and `[0-8][0-9]` matched the `12` inside
`120`. The Sayanox pattern engine supports `*`, `+`, classes, ranges and `$`, but
not alternation `(a|b)` — verified by probe, not assumed.
